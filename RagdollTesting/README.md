# RagdollTesting
Generated by [Rojo](https://github.com/rojo-rbx/rojo) 7.7.0-rc.1.

**Run Rojo from this folder** (`RagdollTesting`), not the parent repo — `rojo serve` must use `default.project.json` here.

If Studio Output shows scripts as **`Server - Server`** and **`Client - Client`**, you are syncing the **parent `RobloxCursor`** project (nested `Server` / `Client` folders), not this folder. Either point Rojo at `RagdollTesting/default.project.json`, or use the copy of the ragdoll code under **`RobloxCursor/src/`** (same logic as here).

Ragdoll code lives under `src/`:

- `src/server/init.server.luau` — server ragdoll + creates `RagdollRemotes` / `RagdollToggle` if missing  
- `src/client/init.client.luau` — **R** via `UserInputService` + `ContextActionService` → `FireServer`  
- `src/shared/RagdollConfig.luau` — cooldown / remote name  

`ReplicatedStorage.RagdollRemotes` is also defined in `default.project.json`; the server still creates it at runtime so an unsynced place file can recover.

After syncing, check **Output** (F9): you should see `Server ragdoll ready` and `Client loaded`.

## Getting Started
To build the place from scratch, use:

```bash
cd RagdollTesting
rojo build -o "RagdollTesting.rbxlx"
```

Next, open `RagdollTesting.rbxlx` in Roblox Studio and start the Rojo server:

```bash
cd RagdollTesting
rojo serve
```

For more help, check out [the Rojo documentation](https://rojo.space/docs).
